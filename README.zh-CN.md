# zhiyan-tedify

把一次性的点评变成可重复的训练闭环——场景、录音、声学证据、转写、任务、复测。

<sub>Markdown · Python · 产品方案与策划文档</sub>

---

## 问题

学生在准备路演时会同时撞上三件事：知道内容但说不清、练了没有反馈、反馈也没变成下一步该做什么。

大多数工具只解决其中一件。这份方案处理的是整条闭环：

```
选择场景 → 录一次基线 → 提取声学证据
→ 确认转写文本 → 生成任务 → 重录并对比
```

## 三个设计决定

**录音优先，而不是文字优先**

早期版本用文字输入做主入口。它能证明诊断链路存在，但评价不了语速、停顿、填充词、是否像在读稿、语感是否自信。

于是录音成为入口，文字输入退为分析文稿的备用手段。

**本地声学分析，不上传音频**

语速、停顿、填充词比例、响度变化都在浏览器里算。离开这台机器的只有统计量，不是录音。这既是隐私决定，也是成本决定。

**每条发现都绑定证据**

一条诊断必须指出是哪一句话、哪一个停顿、哪一个指标造成的。只给分数无法行动。

## 值得一看的部分

**方向决策文档**里有五个候选产品 × 五个维度的打分对比——其中**低成本本身也是一个打分维度**，因为对学生项目来说，能不能零成本做出来和创意好不好同样重要。

每个被否掉的方向记录的是具体资源门槛（「需要文旅方配合」「需要真实的乡村服务资源」），而不是一句「不合适」。

文档里还写死了一条边界：**没有记录，就不把准确率、用户数、营收写成成果。**
