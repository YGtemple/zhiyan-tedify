# 2026 中国国际大学生创新大赛项目申报初稿

## 一、项目定位

### 建议项目名称

**智言：面向大学生创新创业路演的 AI 语音表达训练平台**

英文名可暂用：**TEDify Campus**。

### 建议申报路径

- 赛事：2026年中国国际大学生创新大赛
- 赛道：高教主赛道
- 组别：本科生组·创意组
- 项目类别：人工智能+（以学校网报系统实际选项为准）
- 所属学院：外国语学院
- 项目负责人专业：外国语学院翻译专业
- 现阶段项目类型：创意类/创新类，最终以学校网报系统的选项为准

## 二、为什么这个方向适合你

1. 你是翻译专业学生，具备语言表达、跨文化沟通与教育场景洞察；项目同时面向全校学生的路演、展示和面试需求，不被单一学科限制。
2. 你已经有「智言（TEDify V2）」原型、工作流、API 和前端，不需要从零编故事。
3. 你已有 C++ 算法竞赛、AIGC 和 AI 应用全栈能力，可以承担技术负责人和产品负责人角色。
4. 你的竞赛经历包括码蹄杯省赛银奖晋级国赛、黑客松最佳创新奖、Trae 郑州线下赛最佳人气奖，适合在计划书中证明项目执行能力。
5. 往年外国语学院项目中已有大量泛化的语言教育、翻译器和 AI 教育项目，本项目应聚焦「可测量的表达能力提升」和「创新创业路演训练」，避免只写成普通 AI 写作工具。

## 三、项目摘要（网报和计划书初稿）

大学生在课堂展示、创新创业路演、求职面试、社团竞选和英语交流中，普遍面临「知道内容但说不清、练习没有反馈、反馈无法转化为下一轮行动」的问题。现有工具多聚焦文稿生成、单点语言评分或一次性点评，难以形成面向真实场景的持续训练闭环。

「智言」是一套面向大学生创新创业路演的 AI 语音表达训练平台。项目以真实录音为训练起点，结合浏览器本地声学活动分析、用户确认的转写文本、路演 Rubric 评价和可控的 AI 分析工作流，为用户提供基线测试、语音证据、内容结构诊断、重点问题定位、个性化训练任务和前后对比报告。首期只聚焦 90 秒或 3 分钟路演中「问题—方案—价值」讲不清的高频断点；课堂展示、求职面试和英文展示作为完成校内路演验证后的扩展场景。

项目已完成可运行原型和核心工作流设计，具备表达画像、六步训练闭环、问题绑定证据、下一轮成功标准和进步报告等基础能力。后续将通过校内学生试用、路演前后测评和匿名问卷，验证平台对表达清晰度、结构完整度和训练完成率的改善效果。项目以真实表达训练为应用入口，以 AI 工作流为技术支撑，形成「评估—训练—复测—进步」的低门槛表达能力提升服务。

## 四、要解决的核心问题

### 1. 表达问题缺少结构化诊断

学生通常只能得到「流畅/不流畅」或一个总分，无法知道问题出在开场、观点、证据、转场、结尾还是语气风格。

### 2. 一次反馈没有变成训练行动

传统批改结束后，学生不知道下一次应该练什么，也缺少清晰的达标标准。

### 3. 不同场景使用同一套评价标准

课堂汇报、商业路演、求职面试和英语演讲的评价重点不同，通用评分容易失去指导价值。

### 4. 双语表达训练割裂

学生在中文逻辑组织和英文跨文化表达之间反复切换，但多数工具只覆盖单语、单技能或单次练习。

## 五、产品方案

### 核心闭环

```
选择表达场景 → 完成基线录音 → 提取本地声学证据
→ 补充转写文本 → 生成训练任务 → 复测并形成进步报告
```

### 三个设计支点

**① 录音优先，而非文字优先**

首期把「浏览器本地录音」作为主入口，文字输入降级为转写补充。

这是产品迭代日志里的关键改动——v0.1 版原本用文字输入做主入口，
但那样就退化成普通 AI 写作工具，与「表达训练」无关。

**② 本地声学证据，不上传原始音频**

声学活动分析（语速、停顿、填充词、响度变化等）在浏览器本地完成，
只把统计结果而不是原始音频送到服务端。

这既是隐私设计，也是成本设计。

**③ 问题必须绑定证据**

每条诊断结论都要指出「是哪一句话、哪一段停顿、哪个指标」触发的，
而不是只给一个分数。

## 六、技术路线（低成本）

### 六步训练闭环

1. **场景选择** — 路演 / 课堂展示 / 面试 / 英语演讲
2. **基线录音** — 浏览器 MediaRecorder 本地录制
3. **声学证据提取** — Web Audio API 本地分析
4. **转写确认** — 用户确认或修正转写文本
5. **训练任务生成** — Rubric + AI 工作流产出定向任务
6. **复测与进步报告** — 前后对比，量化改善

### 技术选型原则

- **前端优先**：核心体验在浏览器完成，不依赖 App 分发
- **本地优先**：声学分析、录音、报告渲染全部本地
- **API 可控**：AI 分析走可控工作流，支持多模型切换
- **成本可承受**：优先用免费额度与本地算力

## 八、验证计划

### 试点规模

- 问卷：**30 份**
- 深度访谈：**5–8 次**
- 平台试用：**5–8 次**（含基线录音 + 复练录音）

### 要验证的三个假设

1. **有效性假设**：使用平台后，路演的「问题—方案—价值」断点减少
2. **完成率假设**：任务化的训练比泛泛建议更能让用户练完
3. **场景假设**：路演场景优先于课堂/面试场景

## 九、差异化定位

| 常见做法 | 智言的做法 |
|---|---|
| 生成一份讲稿 | 训练「怎么讲出来」 |
| 给一个流畅度总分 | 指出具体是哪一句、哪个停顿 |
| 一次性点评 | 基线 → 训练 → 复测 → 进步报告 |
| 通用评分 | 分场景 Rubric（路演/课堂/面试/英文） |
| 上传原始音频 | 本地分析，只传统计结果 |

## 这份申报文档的写法要点

### ① 用「为什么适合你」代替「项目背景」

第 2 部分不是常规的市场背景，而是直接回答
「为什么是你能做这件事」——专业能力、已有原型、
技术储备、竞赛履历、同赛道差异化。

**这一节是创意组申报的关键**：评审要看的是
「这个人做这个项目的合理性」，不是市场规模。

### ② 主动划小首期范围

> 首期只聚焦 90 秒或 3 分钟路演中「问题—方案—价值」
> 讲不清的高频断点；课堂展示、求职面试和英文展示
> 作为完成校内路演验证后的扩展场景。

不贪多。先打透一个场景，再谈扩展。

### ③ 问题部分拆到具体痛点

第 4 部分四个问题都写到**具体的场景细节**：
- 「只能得到流畅/不流畅，无法知道问题出在开场、观点、
   证据、转场、结尾还是语气风格」
- 「学生不知道下一次应该练什么，也缺少清晰的达标标准」

不写「用户体验差」这类空话。

### ④ 技术路线强调「低成本」

第 6 部分的原则是前端优先 / 本地优先 / API 可控 / 成本可承受。
对学生项目来说，这是可执行性的证明。

### ⑤ 验证计划给具体数字

30 份问卷、5–8 次访谈、5–8 次试用。
而且要验证的三个假设是**可以证伪的**——
如果完成率假设不成立，说明任务化设计无效，
而不是含糊地「验证用户满意度」。

比文字描述直观得多。
