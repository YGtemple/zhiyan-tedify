# 智言：作品研究与低成本路线

## 结论先行

最终主方向不再是泛化的「AI 英语学习工具」，而是：

> **智言：面向大学生创新创业路演的 AI 语音表达训练平台**

第一阶段只服务创新创业路演场景，解决大学生在 90 秒或 3 分钟表达中讲不清「问题—方案—价值」的断点；课堂展示、求职面试和英文展示在完成路演试点后再扩展。产品核心不是「给一个分数」，而是把一次表达变成可复测的训练闭环：

```
表达场景 → 真实录音 → 本地声学证据 → 转写补充 → 训练任务 → 复测报告
```

这个方向既吸收了现有 `zhiyan` 的训练闭环，又能继续使用 `rongyan` 的英语展示经验。第一阶段不需要服务器、账号、数据库或训练模型：浏览器可本地录音、回放、计算时长/声学活动/停顿等基础信号；转写文本用于补充语速、口头填充词和内容结构。后续再按真实试用需要接入转写或模型 API。

## 一、官方规则给出的硬约束

官方高教主赛道规则明确：本科生组分为创意组和创业组，并按照新工科、新医科、新农科、新文科、「人工智能+」设置项目类型；创意组要求「较好的创意和较为成型的产品原型或服务模式」，且通知下发前尚未完成工商等登记注册。

高教主赛道团队不少于 3 人、不多于 15 人，项目必须由团队实际策划或经营，不得借用他人项目。当前作品按本科生组·创意组推进，不以注册公司、营收或完整商业软件作为第一阶段前置条件。

## 二、公开作品和教程的提炼

### 1. 赛事评审细则：作品不能只有页面

官方 2025 评审规则把高教主赛道创意组分成四块：**个人成长 30 分、项目创新 30 分、产业价值 25 分、团队协作 15 分**。

对本项目的直接要求是：

- **个人成长**：必须能讲清楚翻译专业、算法/AIGC/全栈能力如何在作品中形成交叉能力。
- **调研深入**：必须有学生、教师或创新创业团队的一手访谈/问卷，不能只引用行业报告。
- **项目创新**：必须把「表达诊断」变成具体问题证据和下一步任务，不能只显示 AI 分数。
- **产业价值**：要有清晰客户路径，优先从校内创新创业课程、就业指导和语言展示场景切入。
- **团队协作**：成员分工要围绕产品、用户研究、前端和运营形成互补。

### 2. 路演教程：页面围绕一个判断组织

公开的竞赛 PPT 方法论强调：每页只承担一个核心判断，先讲问题和证据，再讲产品、创新、市场、团队与路线；数据必须标注来源，不能把预测指标写成已有成果。这个原则会用于后续 PPT，但不直接复制任何模板素材。

### 3. 英语学习产品：真正有产品感的不是功能数量

公开项目里值得吸收的结构：

- **GPT Wordbook**：把单词解释、词根词缀、文化背景、关联词汇组织成内容网络，采用静态站点和响应式设计。
- **Word Teacher**：用场景、跟读、对话、评分和进度追踪形成学习闭环，但它的完整教师后台、数据库和语音服务不适合当前低成本阶段。
- **LinguaPal**：强调自主上传材料、个性化路径和本地化存储，适合借鉴隐私和「一人一策」的叙事。
- **FlashWord**：把固定目标词嵌入语境，再转入学习/掌握/复习状态；本项目将其「约束内容—即时反馈—状态变化」的思路改造成「问题—任务—复测」。

### 4. 你现有仓库：保留基础，重做定位

- **rongyan**：已有 HTML 写作页面、考试类型、作文输入、字数统计、标签页、句式库和本地存储结构，但原页面的 API 为空，分析结果主要仍是占位内容。
- **zhiyan**：已有 TEDify V2 网页架构、17 项表达画像、评分 Rubric、问题到训练任务的映射、进步流和数据模型文档，是新方向更有价值的基础。

最终采用「**zhiyan 的产品逻辑 + rongyan 的外语展示场景 + 全新无后端演示前端**」。

## 四、产品版本定义

### 现在就做：语音优先的离线 MVP

- 单文件 HTML/CSS/JavaScript，不接后端、不接数据库、不需要 API Key。
- 使用浏览器 `MediaRecorder` 本地录音和回放；音频不上传到服务器。
- 通过浏览器声学活动监测生成真实的时长、活动占比和有效停顿基础数据。
- 使用用户提供的转写文本，补充语速、口头填充词和结构连接词等内容信号。
- 支持场景选择、录音、试听、转写、训练报告、问题证据、短任务和复练入口。
- **内置一套明确标注为「演示数据」的报告**，保证答辩现场没有麦克风时仍可完整展示流程。

### 后续可实现：低成本升级

- 接入语音转写能力，将用户确认后的转写结果自动填入当前页面；优先评估浏览器能力或按量 API。
- 接入任一文本模型 API，只替换「文本证据 → 问题与任务」的结果来源，前端数据结构不变。
- 不承诺医学、心理或专业发音测评，不把本地音量阈值包装成情绪识别或发音准确率。
- 将 Rubric、问题库和任务库拆成 JSON 文件，支持不同课程和赛事场景。
- 使用 Netlify、GitHub Pages 或学校服务器部署静态版本，成本可控制为 0。

### 暂不做

- 不做用户注册、教师后台、支付、数据库和复杂权限。
- 不训练专属大模型。
- **不把「准确率、用户数、营收、提升比例」写成成果，除非有真实记录。**
- 不同时做英语写作、单词、口语、旅游和非遗五个产品，首版只服务表达训练主闭环。

## 五、获奖导向的证据规划

作品后续必须补齐四类证据：

1. **作品证据**：网页原型、产品流程图、场景 Rubric、架构图、演示视频。
2. **用户证据**：20—30 份问卷，8—10 次访谈，至少 5 人完成一次原型试用。
3. **个人证据**：翻译专业课程背景、码蹄杯省赛银奖、AIGC/全栈项目、黑客松和表达类竞赛经历。
4. **团队证据**：负责人、用户研究、前端/数据、运营材料四类分工，以及真实过程记录。

## 六、工作顺序

### 第一阶段：作品成型
完成静态网页、产品说明、演示流程和截图。

### 第二阶段：调研验证
围绕「学生知道内容但说不清、反馈不能变成任务、不同场景评价标准不同」设计问卷和访谈，形成统计图表和原始记录。

### 第三阶段：书面材料
根据真实产品写 Word 计划书、路演 PPT/PDF、调研报告和 1 分钟演示脚本。材料中的每一个数字和成果都能回到作品或调研证据。

### 第四阶段：低成本增强
根据学校初赛反馈决定是否接入 API、语音转写或真实试用，不在报名阶段为复杂后端投入不必要成本。

## 七、边界说明

这个方向可以明显提高项目的一致性、可信度和展示质量，但**不存在「做完就很大概率获奖」的保证**。能否获奖还取决于学校名额、同组项目、团队答辩和真实调研质量。当前最有效的策略是尽快形成一个能演示、能验证、能讲清个人成长的作品，再用真实证据提升而不是靠包装堆砌。

## 这份文档的方法论价值

### ① 候选方向用多维评分表决策

五个候选方向 × 五个维度（个人成长/项目创新/产业价值/团队可讲性/低成本），
打分 1—5。最后「智言」总分 24/25 拿下主方向。

**注意「低成本」也是一个打分维度**——对学生项目来说，
能不能用零成本做出来，和创意好坏同等重要。

### ② 每个被否方向都写了理由

| 被否方向 | 理由 |
|---|---|
| AI+非遗国际传播 | 同质化和实地调研压力较大 |
| AI乡村学校英语服务 | 只有真实乡村服务资源时再考虑红旅 |
| AI智慧伴游 | 需要文旅场景与用户资源 |

不写「不适合」这种模糊判断，写**具体的资源门槛**。

### ③ 明确划定「暂不做」清单

四条「暂不做」里最关键的是：

> 不把「准确率、用户数、营收、提升比例」写成成果，除非有真实记录。

这是给自己设的红线——防止在答辩材料里
把预期写成成果。第 7 部分「边界说明」
同样如此：「不存在『做完就很大概率获奖』的保证」。

### ④ 现有仓库的取舍写得很清楚

「rongyan 的 API 为空，分析结果主要仍是占位内容」
「zhiyan 更有价值的基础」

不因为是自己写的就都保留，**按实际可用度判断**。
最终组合：zhiyan 产品逻辑 + rongyan 外语场景 + 全新无后端前端。

### ⑤ MVP 内置「演示数据」

「内置一套明确标注为『演示数据』的报告，
保证答辩现场没有麦克风时仍可完整展示流程」

这是很实际的考虑——答辩现场设备出问题
是大概率事件，产品要能降级运行。

### ⑥ 工作顺序按「先验证再包装」

第一阶段作品 → 第二阶段调研 → 第三阶段书面材料
→ 第四阶段按反馈增强。

材料放最后写，且要求
「每一个数字和成果都能回到作品或调研证据」。
