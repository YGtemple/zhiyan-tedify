# 智言：重点项目冲刺包

## 一、重点项目版定位

**智言：面向大学生创新创业路演的 AI 语音表达训练平台**

首期只解决一个明确问题：大学生有项目内容，却在 90 秒或 3 分钟路演中讲不清「为谁解决什么问题、凭什么有效、为什么值得支持」。

课堂展示、求职面试和英文展示不再与路演平行竞争资源，而是作为验证路演闭环后可扩展的场景。重点项目筛选阶段只展示一条最短、最可信的路径：

```
真实路演录音 → 本地声学与转写证据 → 路演 Rubric → 三项短任务 → 同场景复练
```

## 二、四人团队配置

| 角色 | 专业基础 | 负责工作 | 必须留下的过程证据 |
| --- | --- | --- | --- |
| 项目负责人 | 翻译专业 | 路演场景设计、双语表达 Rubric、用户访谈统筹、答辩 | Rubric 迭代记录、访谈纪要、答辩讲稿版本 |
| 技术负责人 | 计算机专业 | 浏览器录音、前端迭代、语音/转写接口评估、数据整理 | Git 提交、功能截图、测试问题单、技术说明 |
| 内容与测评成员 | 英语专业 | 英文路演素材、表达任务、示范文本、双语内容校对 | 场景题库、示范样例、修改记录 |
| 用户研究与运营成员 | 英语专业 | 问卷发放、试用招募、访谈记录、视频和材料归档 | 原始问卷、匿名访谈编号、试点签到、视频素材 |

> 分工不是最后写在 PPT 上的四句话。每人至少保留 3 份实际产出，并在答辩中用「谁做了什么、产生什么修改」说明协作过程。

## 三、两周试点目标

不追求大样本或夸张效果，重点是形成一条完整证据链。

| 阶段 | 时间 | 团队动作 | 可获得证据 |
| --- | --- | --- | --- |
| 准备 | 第 1-2 天 | 确认 4 人角色；只保留路演主场景；统一 90 秒题目与 Rubric | 团队分工表、路演题目、v0.2 页面截图 |
| 需求验证 | 第 3-5 天 | 发放问卷，完成至少 5 次访谈 | 原始答卷、匿名访谈纪要、问题优先级图表 |
| 原型试用 | 第 6-10 天 | 邀请 5-8 名有路演/汇报经验的学生完成基线录音、任务、复练 | 授权记录、脱敏录音编号、前后报告、可用性问题单 |
| 结果整理 | 第 11-12 天 | 统计任务完成情况、最常见问题、用户建议；不夸大提升幅度 | 试点表格、图表、原话摘录、版本迭代记录 |
| 筛选材料 | 第 13-14 天 | 录制 1 分钟产品视频；更新 PPT、计划书和答辩稿 | 视频、PPT v2、计划书 v2、重点项目申请陈述 |

## 四、学校筛选时必须讲清的五件事

1. **为什么是路演**：学校正在组织创新大赛，参赛团队本身就是可立即触达的真实用户；产品服务学校现有双创训练场景。
2. **为什么不是普通录音机**：智言不止录音，而是把路演中的声音节奏和内容结构转成带成功标准的短任务，并要求同场景复练。
3. **为什么是这个团队**：翻译专业负责跨语言和场景表达逻辑，两名英语专业成员负责内容与用户试点，计算机专业成员确保产品真实可运行。
4. **现在做到了什么**：浏览器本地录音、回放、时长/活动量/停顿估算、转写补充、问题报告和训练任务已经可演示。
5. **学校支持后能获得什么**：进入双创训练营或课程场景，获得真实试用样本、教师 Rubric 指导和路演团队反馈，可在两周内形成第一轮校内验证报告。

## 五、必须收集的材料

### 团队材料

- 四位成员的真实姓名、年级、完整专业名称、手机号/邮箱（**仅填学校系统，不公开展示**）。
- 每人 2-3 个与本角色相关的真实经历或技能；**不写无法证明的奖项和能力**。
- 每人一张干净的证件照或半身照，后续放团队页和 PPT。
- 团队讨论记录、任务分配截图或会议纪要至少 3 次。

### 试点材料

- 路演训练问卷 30 份以上原始答卷。
- 5-8 次访谈的匿名纪要（含原话摘录）。
- 5-8 人完成基线录音 + 训练任务 + 复练的完整记录。
- 授权使用的脱敏录音编号与前后报告。

## 这份冲刺包的方法论价值

### ① 「必须留下的过程证据」一列

团队配置表不是只写分工，而是给每个角色配一列
**「必须留下的过程证据」**：

| 角色 | 过程证据 |
|---|---|
| 项目负责人 | Rubric 迭代记录、访谈纪要、答辩讲稿版本 |
| 技术负责人 | Git 提交、功能截图、测试问题单、技术说明 |
| 内容与测评 | 场景题库、示范样例、修改记录 |
| 用户研究与运营 | 原始问卷、匿名访谈编号、试点签到、视频素材 |

并且写了一句硬要求：

> 分工不是最后写在 PPT 上的四句话。每人至少保留 3 份实际产出，
> 并在答辩中用「谁做了什么、产生什么修改」说明协作过程。

**团队协作分 15 分不能靠 PPT 上的四行分工拿**，
得有过程证据。

### ② 两周试点按天拆，且每阶段绑定产出

| 阶段 | 天数 | 产出 |
|---|---|---|
| 准备 | 1-2 | 分工表、题目、页面截图 |
| 需求验证 | 3-5 | 答卷、访谈纪要、图表 |
| 原型试用 | 6-10 | 授权记录、脱敏录音、前后报告 |
| 结果整理 | 11-12 | 试点表格、图表、原话摘录 |
| 筛选材料 | 13-14 | 视频、PPT v2、计划书 v2 |

每个阶段的「团队动作」和「可获得证据」一一对应。
14 天排满，没有空档。

### ③ 「不夸大提升幅度」写进流程

结果整理阶段明确写了：

> 统计任务完成情况、最常见问题、用户建议；
> **不夸大提升幅度。**

这句话出现在执行计划里，而不是原则声明里——
说明它是作为**操作要求**存在的。

### ④ 「必须讲清的五件事」是答辩预演

第 4 部分列的五问（为什么是路演 / 为什么不是录音机 /
为什么是这个团队 / 现在做到了什么 / 学校支持后获得什么）
基本覆盖了评委必问的问题。

第 2 问「为什么不是普通录音机」尤其重要——
这是产品最容易被质疑的点，提前准备好了应答。

### ⑤ 隐私边界写清楚

> 真实姓名、年级、完整专业名称、手机号/邮箱
> **仅填学校系统，不公开展示**。

第 3 部分也要求「授权记录、脱敏录音编号」。
做用户研究必须一开始就处理授权和脱敏，
不是事后补。
